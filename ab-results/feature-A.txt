What I changed

- build.mjs: added `changelogVersion(text)` (new top-level function) plus the check
  beside the existing worker-BUILD guard — it reads CHANGELOG.md, takes the first
  `## <version> —` heading (skipping non-version headings like `## Repository, …`)
  and pushes onto `fails` when it is missing or disagrees with the manifest version.
- extension/test.mjs: new end-of-file section that lifts `changelogVersion` and the
  check block out of build.mjs by pattern and runs both — the passing case (heading
  matches the manifest: no failure), the failing cases (stale heading, no heading at
  all: one failure naming both numbers), plus the real CHANGELOG.md against the real
  manifest.

Runs: `npm test` 3 times (all green; plus one `npm run test:extension` on its own
while reading the new section's output), `node build.mjs` 2 times — once in the repo
(exit 0) and once in an isolated copy of the tree with the heading set to 0.9.94, to
confirm the check fails the build end to end (`BUILD FAILED — version mismatch:
extension manifest=0.9.95 CHANGELOG.md=0.9.94`, exit 1). Nothing was skipped,
disabled or weakened.

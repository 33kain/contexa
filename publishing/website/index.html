CONTEXA

Every token earned

Overview · How it works · Privacy · Notes · Source

CONTEXA is a Chrome extension for claude.ai. When Claude finishes a reply, one trigger appears above the message box. The reply itself has been copied from the page, and that is all: nothing else has been read, and nothing has been sent or spent. Press it, and the extension reads your own messages from the whole conversation (not Claude's earlier replies) and sends them with the reply just received. It comes back with up to four next messages, each written in full. Click one and the whole text lands in the message box, unsent. You edit it and send it yourself. It never sends on your behalf.

Every message has to be earned by a verbatim quote from the conversation or the reply, checked before it is drawn. When nothing qualifies, nothing is drawn. The point of all of it is the messages you do not have to send: on a long conversation each one costs the whole conversation to re-read, and the section below puts a number on that. Free, no account, 20 presses a day per device; your own API key removes the limit. Version 0.9.71, MIT, source on GitHub.

Install it from the Chrome Web Store. Which browsers can, and how to tell it is working, are under Install below.

Save tokens. Extend your sessions.

On claude.ai, every message you send is processed with the whole conversation behind it. The cost of a message is not its length; it is how deep into the session you are when you send it. A wasted message on a forty-message thread costs a forty-message read. Three kinds of message get wasted, and none of them is a bad answer from Claude: the vague follow-up that comes back as a question ("which part?"), the three-jobs-in-one ask that comes back as three half-answers, and "explain that again", which re-reads everything to restate what is already on screen.

CONTEXA writes the next message as one finished request. One job, one verb. The defaults the session already settled are stated on an Assume: line, so Claude does not ask. The material only you have is a <paste here> slot, so Claude does not ask for that either. A message that cannot draw a clarifying question is a round trip that never happens, and on a long session that round trip is the expensive one. Fewer messages per thing done is how the usage limit lasts longer.

The table is a model, not a measurement, and it says so. An ask is one thing you want done. Each exchange is taken as about 150 tokens from you and 900 from Claude. Without CONTEXA an ask is taken to cost 1.7 messages on average, because some asks need a clarifying reply or a redo; with it, 1.1, allowing for the occasional edit. Tokens read is the sum, over every message sent, of the conversation as it stood at that moment.

The percentage barely moves with session length. The absolute number is what grows: on the forty-ask session the difference is over a million tokens of re-reading, which is why the saving is felt most on exactly the sessions that hit the limit. Three things are worth knowing before repeating any of it. The whole estimate rests on how many messages an ask costs you today; if your sessions rarely need a clarifying round, the saving is nearer 20 to 30 percent. claude.ai almost certainly caches context, so a re-read message costs less than a fresh one, and how much of that reaches your usage limit is not published; treat the message counts as the firm figure and the token figures as the ceiling. And CONTEXA's own call is small next to any of this: at most about 4,500 tokens per press, on its own backend or your own API key, and none of it counts against your claude.ai usage.

The rule behind this is the product's motto, every token earned: a token is earned when its message could not have been shorter, could not have been skipped, and will not need a follow-up to fix. The full argument, with each rule tied to the code that enforces it, is in the token-savings thesis.

Quick start

  1. Install it from the Chrome Web Store.
  2. Open claude.ai and ask something that takes a paragraph to answer; a reply under 120 characters gets no trigger. When the reply finishes, the mascot appears above the message box. The reply has been copied from the page; nothing else has been read, and nothing has been sent.
  3. Press it. This spends one of the day's 20. A row of up to four moves appears, or a one-line notice says nothing was earned and removes itself.
  4. Click a move. The whole prompt is in the box, unsent, and picking it cost nothing. Edit it if you want, then send it yourself.

What it does

It reads your messages across the conversation

A follow-up written from the last answer alone is mostly about the last answer. So when you press, it reads your own messages across the conversation as the page holds it: the earliest one it can see, which is usually the first and usually where you said what you were trying to do, and everything you kept coming back to since. On a very long conversation the page holds only its tail; that limit is stated under Known limits. Claude's reply is material, not the subject; what it just built is what makes a new move possible. A move that sends you back over an answer you have already read is the one thing it is written never to offer.

Each move stands alone

Each move is one complete prompt with one ask, ready to send. The moves do not run in order and do not build on each other; picking one discards the rest. Where a prompt needs something only you have (a file, a link, a story only you can tell) it writes <paste here> instead of inventing it. Where the conversation already settled something, it may add a line starting Assume:, so you can change it before you send rather than discover it in the answer.

Zero is a valid outcome

Every move must be earned by a verbatim quote from something actually said in the conversation, by you or by Claude, and that is checked before anything reaches your screen. When nothing is earned, no row is drawn, and no suggestion is shown only because it could be. On a one-question chat that is the usual result, and the correct one. How often it happens in real use is the open question the current field test exists to answer.

What it will not do

  • Send anything on your behalf. The message box is where you see the full text before anything goes.
  • Read Claude's earlier replies, your other conversations, or any other site.
  • Store your conversation text.
  • Rewrite what you typed. There is nothing to type into; clicking is the only input.
  • Grade your prompts or tell you how to write.
  • Overlay the message box, interrupt you mid-sentence, or keep a conversation going on its own.
  • Show canned suggestions when something fails. A limit reached, a parse failure or a network error is reported as what it is.

Compared with other prompt extensions

Every "prompt" extension we could find either rewrites what you already typed or saves snippets for later. We didn't find one that reads your whole session and writes the next message for you, complete and ready to send.

It is for people who already use Claude every day, developers or not. It does not grade prompts: making bad prompts good is worth nothing to someone whose prompts are already good. The parts of the mechanism that are worth knowing before you trust it are on How it works; what leaves your browser, and when, is on Privacy.

Install

Install it from the Chrome Web Store. It is free. There is no account, no sign-up and no API key to enter. 20 presses a day per device are included, reset at midnight UTC, and picking a move costs nothing.

Chrome for Android, Safari on iOSNo. They cannot install extensions from the Chrome Web Store, and most mobile browsers cannot.

Your own API key

Add it in the extension's settings. The daily limit goes away, and requests go from your browser to api.anthropic.com only; no CONTEXA server is involved. The key is stored on your device and is sent nowhere else. Use under your own key falls under your own agreement with Anthropic.

How to tell it is working

Open claude.ai and ask something that takes a paragraph to answer. When the reply finishes, the mascot appears above the message box; hover or tab to it and it asks What now? If it does not appear, one of three things is true. The reply was under 120 characters, which never gets a trigger. CONTEXA is switched off in its settings. Or claude.ai changed its page structure and the extension went quiet, which is what it is built to do instead of breaking the page.

Developer install

chrome://extensions → Developer mode → Load unpacked → the extension/ folder of the source.

Chrome will warn that it cannot verify where an unpacked extension comes from. That is expected, and it goes away only when installing from the store.
